## Priority Roadmap

### 🔴 PRIORITY 0: PreToolContent Persistence & Context Enrichment

**Status:** 🔄 IN PROGRESS

**Problem:** Messages generated by the assistant before tool calls (`PreToolContent`) are not saved to the database or indexed for search. This results in:
1. Important context being lost between sessions
2. Semantic searches (`/search`, `remember()`) not finding this content
3. Incomplete conversation history

**Solution:** Save `PreToolContent` as separate messages with type `pre_tool_content`, and modify the enrichment system to fetch multiple subsequent messages.

---

**Architecture:**

```
┌─────────────────────────────────────────────────────────────────┐
│                    Message Flow                                 │
├─────────────────────────────────────────────────────────────────┤
│  User Query                                                     │
│       ↓                                                         │
│  CustomCoordinator.process_response()                           │
│       ↓                                                         │
│  PreToolContent generated ───→ Accumulate in coordinator        │
│       ↓                                                         │
│  ToolCalls executed                                             │
│       ↓                                                         │
│  Final response generated                                        │
│       ↓                                                         │
│  Return SendMessageResult {response, pre_tool_content}          │
│       ↓                                                         │
│  REPL: add_pre_tool_message() ← Save FIRST                      │
│       ↓                                                         │
│  REPL: add_assistant_message() ← Save LAST                      │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                    Database Schema                              │
├─────────────────────────────────────────────────────────────────┤
│  messages table:                                                │
│    id INTEGER PRIMARY KEY                                       │
│    conversation_id TEXT                                         │
│    role TEXT ('user', 'assistant', 'system', 'tool')            │
│    content TEXT                                                 │
│    timestamp INTEGER                                            │
│    message_type TEXT DEFAULT 'normal'  ← NEW                    │
│    previous_message_id INTEGER         ← NEW                    │
│                                                                 │
│  message_types: 'normal', 'pre_tool_content'                   │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                    Retrieval Flow                               │
├─────────────────────────────────────────────────────────────────┤
│  build_context(user_query)                                      │
│       ↓                                                         │
│  search_hybrid(query) → Vec<SearchResult>                       │
│       ↓                                                         │
│  enrich_with_context(results):                                  │
│    For user message:                                            │
│      → get_subsequent_assistant_messages(after_id, limit=5)    │
│      → filter duplicates                                        │
│    For assistant message (isolated):                            │
│      → subsequent_messages = []                                │
│       ↓                                                         │
│  format_retrieved_context(results):                             │
│    For each result:                                             │
│      → Print main message                                       │
│      → Print subsequent_messages (with [Intermediate] prefix)   │
└─────────────────────────────────────────────────────────────────┘
```

---

**Implementation Plan:**

| Phase | File | Changes |
|-------|------|---------|
| 1 | `src/db/schema.rs` | `SCHEMA_VERSION = 5`, add `message_type`, `previous_message_id` columns |
| 1 | `src/db/connection.rs` | Migration v4→5 |
| 1 | `src/db/operations.rs` | `insert_message_with_type`, `get_subsequent_assistant_messages`, `get_previous_message_id`, modify `enrich_with_context`, update `SearchResult` |
| 2 | `src/chat/custom_coordinator.rs` | `PreToolContent` struct, accumulators, `take_pre_tool_content()` |
| 2 | `src/chat/repl.rs` | `SendMessageResult` struct, extract and save PreToolContent |
| 3 | `src/chat/session.rs` | `SavedMessage` struct, `add_pre_tool_message()` |
| 3 | `src/tools/remember.rs` | Update ID retrieval with navigation, update query with subsequent_messages |
| 4 | `src/retrieval/context_builder.rs` | `format_retrieved_context()` with subsequent messages |
| 4 | `src/prompts/builder.rs` | Update MEMORY TOOLS section with navigation hints |
| 5 | Tests | New tests for enrichment, persistence, navigation |

---

**Key Decisions:**

| Decision | Value |
|----------|-------|
| Limit of subsequent messages | **5** |
| `next_message_id` | Only if not final message |
| `previous_message_id` | Only for assistant messages |
| Retrocompatibility | Not required |
| Thinking format | Keep ` hesitation` tags |
| Concurrency | Technical debt (assume single-threaded per session) |

**Prompt Engineering (MEMORY TOOLS section):**

```markdown
### MEMORY TOOLS
You have access to your conversation history via the remember tool:

- **remember(id="N")**: Get full message by ID
  Use when you see a relevant but truncated message in context.

- **remember(query="topic")**: Search past discussions
  Use when the user asks about something not in current context.

**Navigation:**
Messages include navigation hints:
- `Previous: remember(id="X")` - Message before this one
- `[id=N]` - IDs you can use to retrieve full content

**Message Structure:**
User messages may be followed by multiple assistant messages:
- `[Intermediate]` - Text generated before tool calls
- Without prefix - Final response

Use previous/reply IDs to navigate the conversation thread.
```

---

**Commit Plan:**

1. `feat(db): add message_type and previous_message_id columns (schema v5)`
2. `feat(db): add get_subsequent_assistant_messages and get_previous_message_id`
3. `feat(db): modify enrich_with_context for multiple subsequent messages`
4. `feat(chat): accumulate PreToolContent in CustomCoordinator`
5. `feat(chat): save PreToolContent as separate messages`
6. `feat(session): add add_pre_tool_message method`
7. `feat(retrieval): format subsequent messages in context`
8. `feat(remember): add navigation hints and subsequent messages`
9. `feat(prompts): update MEMORY TOOLS section with navigation`
10. `test: add tests for PreToolContent persistence and enrichment`

---

**Technical Debt:**

1. **Multi-instance concurrency:** If multiple instances run on the same conversation, IDs can be interleaved. Mitigation: Lock by conversation_id (future).
2. **Hardcoded limit:** Limit of 5 subsequent messages is hardcoded. Mitigation: Add to `RetrievalConfig` (future).
3. **Remember tool incomplete:** `previous_message_id` added but `remember` not updated for bidirectional navigation. Mitigation: Update `remember` to accept navigation params (future).

## Streaming Architecture (Future)

The `ollama-rs` library (already included with `stream` feature) provides streaming capabilities:

```rust
// Streaming API
pub async fn send_chat_messages_stream(
    &self,
    request: ChatMessageRequest,
) -> Result<ChatMessageResponseStream>

// ChatMessage includes thinking content
pub struct ChatMessage {
    pub content: String,
    pub thinking: Option<String>,  // For DeepSeek R1, etc.
    // ...
}
```

**Current Status:** Non-streaming only (`send_chat_messages()`)
**Streaming Path:** `send_chat_messages_stream()` or `send_chat_messages_with_history_stream()`

**Implementation Considerations:**

1. **CLI Mode (current):** `termimad` is synchronous, requires block buffering
2. **TUI Mode (future):** Ratatui supports incremental rendering via `tui-markdown`
3. **Thinking Display:** Separate pane in TUI, inline dimmed text in CLI

See: `doc/src/development/roadmap.md` - TUI section for detailed streaming approach
