VERIFICATION: .env blocking scenario
--------------------------------------
When validate_subagent_path() is called with an .env file inside CWD:
1. Path expands and canonicalizes successfully
2. Path starts_with(canonical_cwd) → YES (inside CWD)
3. is_blocked_for_read() → YES (.env matches DEFAULT_BLOCKED_PATTERNS)
4. Returns Err: "Error: BLOCKED - '.env' matches a protected file pattern..."

The blocklist check happens AFTER the sandbox check. Even though the file
is within CWD (passes sandbox), it's still blocked by the blocklist.

Two-layer defense:
- Layer 1: CWD sandbox blocks paths OUTSIDE allowed directories
- Layer 2: Blocklist blocks sensitive files even INSIDE allowed directories

Blocklist correctly blocks .env and other sensitive files within CWD.
