# v0.22.5 - Hotfix: Retrieval After Clear

**Priority:** CRITICAL  
**Status:** COMPLETED ✓  
**Date:** 2026-03-03  

---

## Bug Report

### Symptom

After using `/clear`, the model loses all memory of previous conversation, even though:
- SQLite database still contains the messages
- `compacted_summary` is preserved (if it existed)
- User expects the model to remember context

### User Experience Failure

```
User: "Você poderia fazer uma breve pesquisa sobre as Investigações Filosóficas de Wittgenstein?"
[Model responds with research]
User: "Eu estou aqui com 'Como ler Wittgenstein', do João da Penha..."
[Model responds]
User: /clear
User: "A gente já conversou a respeito do Como ler Wittgenstein?"
Model: "Não tenho memória de conversas anteriores..."
```

**Expected:** "Sim, você mencionou ter o livro 'Como ler Wittgenstein'..."

**Actual:** "Não tenho memória..."

### Root Cause Analysis

Three problems compound to break the feature:

#### Problem 1: `retrieval_enabled` is `false` by default

```rust
// src/chat/session.rs
retrieval_enabled: false,  // ← Disabled by default
```

Even after `/clear`, retrieval doesn't happen because:
- Requires `session.retrieval_enabled = true`
- User must run `/retrieval` manually

#### Problem 2: No compaction means no summary

- `/clear` preserves `compacted_summary`
- But if user never ran `/compact`, `compacted_summary` is `None`
- So `/clear` preserves nothing

#### Problem 3: Retrieval requires 20+ messages

```rust
// src/retrieval/context_builder.rs
pub const MIN_MESSAGES_FOR_RETRIEVAL: usize = 20;
```

Even with retrieval enabled, needs 20+ total messages.

### Why the Flow is Broken

```
User conversation (2-4 messages)
       ↓
User runs /clear
       ↓
session.messages = [] (EMPTY)
session.compacted_summary = None (NEVER COMPACTED)
SQLite messages [intact]
       ↓
User asks about previous conversation
       ↓
should_retrieve() checks:
  - enabled? false ← PROBLEM!
  - count? 4 messages ← BELOW 20
       ↓
No recovery happens
       ↓
Model responds "no memory"
```

## Implementation Plan

### Fix Strategy: Forced Retrieval After Clear

**Approach:** Option B - Retrieval forced after clear

When session is empty but database has messages, ALWAYS attempt retrieval:
- Ignore `retrieval_enabled` flag
- Ignore `MIN_MESSAGES_FOR_RETRIEVAL` threshold
- Show system message to inform user

### Changes

#### 1. New constant for clear-specific retrieval

```rust
// src/retrieval/context_builder.rs
pub const MIN_RETRIEVAL_FORCE_COUNT: usize = 2;  // As low as 2 messages
```

#### 2. Modify `should_retrieve()` to handle forced retrieval

```rust
// src/retrieval/context_builder.rs
pub fn should_retrieve(&self, session: &ChatSession, db: Option<&Arc<Database>>) -> bool {
    // ... existing logic ...
}

/// Check if retrieval should be forced after /clear
pub fn should_force_retrieve(session: &ChatSession, db: Option<&Arc<Database>>) -> bool {
    // Only force if session is empty after clear
    if !session.messages.is_empty() {
        return false;
    }
    
    // Must have summary or db messages
    if session.compacted_summary.is_some() {
        return true;
    }
    
    if let Some(db) = db {
        if !session.anonymous && !session.id.is_empty() {
            if let Ok(count) = db.count_conversation_messages(&session.id) {
                return count >= MIN_RETRIEVAL_FORCE_COUNT;
            }
        }
    }
    
    false
}
```

#### 3. Update `build_context()` to use forced retrieval

```rust
// src/retrieval/context_builder.rs
pub async fn build_context(...) -> ContextResult {
    // ...
    
    // 2. Retrieved messages (if enabled - placed after system to avoid being lost)
    let should_retrieve = config.enabled && config.should_retrieve(session, db);
    
    // 2a. FORCED retrieval after /clear (session empty but DB has messages)
    let force_retrieve = should_force_retrieve(session, db);
    
    if should_retrieve || force_retrieve {
        // ... retrieval logic ...
    }
}
```

#### 4. Post-clear system message

When `/clear` is called and messages are cleared, show a styled message:

```rust
// src/chat/commands.rs - /clear handler
if has_db_messages || session.compacted_summary.is_some() {
    // Use gray styled message (like thinking output)
    eprintln!("\x1B[90m[i] Messages cleared. Semantic retrieval enabled.\x1B[0m");
    eprintln!("\x1B[90m[i] You may ask about previous topics.\x1B[0m");
}
```

Style: Gray text `[i]` prefix, matching thinking/debug output style.

#### 5. Lower MIN_MESSAGES_FOR_RETRIEVAL

```rust
// src/retrieval/context_builder.rs
pub const MIN_MESSAGES_FOR_RETRIEVAL: usize = 5;  // Lowered from 20
```

This makes retrieval useful for shorter conversations.
