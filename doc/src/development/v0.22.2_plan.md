## Executive Summary

This version addresses critical bugs found in stress testing:

1. **Chunking Síncrono** - Garante que chunks sejam salvos mesmo se o processo for interrompido
2. **Recuperação de Embeddings** - Recupera embeddings perdidos na inicialização
3. **Middle Compaction** - Preserva first N + last N mensagens durante compaction

## Architecture

### Context Order (Research-Based)

Based on "Lost in the Middle" phenomenon and provider best practices:

```
┌──────────────────────────────────────────────────────────────────┐
│ 1. SYSTEM PROMPT (~500-2000 tokens)                              │
│    Position: BEGINNING (Claude: "up to 30% better")              │
├──────────────────────────────────────────────────────────────────┤
│ 2. RETRIEVED MESSAGES (~1000-5000 tokens)                       │
│    Position: AFTER SYSTEM (avoid "lost in middle")              │
│    Semantic search from conversation history                     │
├──────────────────────────────────────────────────────────────────┤
│ 3. PRESERVED FIRST MESSAGES (~500-2000 tokens)                  │
│    Position: Before summary (establish context)                  │
│    First N messages (system instructions, initial context)       │
├──────────────────────────────────────────────────────────────────┤
│ 4. COMPACTED SUMMARY (~500-1000 tokens)                         │
│    Position: Before recent (summarized middle section)          │
│    Contains: Entities, decisions, facts from middle messages    │
├──────────────────────────────────────────────────────────────────┤
│ 5. RECENT MESSAGES (~2000-5000 tokens)                           │
│    Position: Before query (avoid "lost in middle")              │
│    Last N messages in full fidelity                              │
├──────────────────────────────────────────────────────────────────┤
│ 6. CURRENT USER QUERY                                            │
│    Position: VERY END (Anthropic: "critical for quality")       │
└──────────────────────────────────────────────────────────────────┘
```

### Middle Compaction Strategy

**Preservation Logic:**

```
Before Compaction (30 messages):
├── [0..5]   First messages    ─┐
├── [5..25]  Middle messages    ├─ All sent to LLM
└── [25..30] Last messages     ─┘

After Middle Compaction:
├── [0..5]   First messages     ← Preserved in context
├── [5..25]  Middle messages    ← Summarized → Summary
└── [25..30] Last messages      ← Preserved in context

Context sent to LLM:
1. System Prompt
2. Retrieved (RAG)
3. First 5 messages (preserved)
4. Summary (middle section)
5. Last 5 messages (preserved)
6. Query
```

**Critical Rule:** Messages are NEVER deleted from SQLite. Only the LLM context changes.

### Chunking Synchronous Flow

**Before (Fire-and-Forget):**
```
add_user_message()
├── Insert message (sync)
└── tokio::spawn(async {
    ├── Insert chunks (async) ← CAN BE LOST
    └── Generate embeddings (async)
})
```

**After (Synchronous Chunks):**
```
add_user_message()
├── Insert message (sync)
├── Insert chunks (sync) ← ALWAYS SAVED
└── tokio::spawn(async {
    └── Generate embeddings (async)
})

On App Restart:
└── recover_missing_embeddings()
    ├── Find chunks with has_embedding=0
    └── Generate embeddings (async)
```

### Phase 2: Middle Compaction Integration

**Goal:** Preserve first N + last N messages during compaction

#### 2.1 Remove Dead Code markers

**File:** `src/context_overflow.rs`

- Remove `#[allow(dead_code)]` from:
  - `DEFAULT_KEEP_FIRST`, `DEFAULT_KEEP_LAST`
  - `get_compaction_range()`, `get_compaction_range_default()`
  - `CompactionSuggestion`

#### 2.2 ChatSession Field

**File:** `src/chat/session.rs`

```rust
/// Range of compacted messages (middle compaction)
/// Some((first_preserved, last_preserved_start)):
///   - [..first_preserved] = preserved at start
///   - [first_preserved..last_preserved_start] = in summary
///   - [last_preserved_start..] = preserved at end
/// None = no compaction
#[serde(default)]
pub compacted_range: Option<(usize, usize)>,
```

#### 2.3 Compact Function

**File:** `src/chat/repl.rs`

- Modify `compact_conversation()` to:
  - Call `get_compaction_range_default()`
  - Summarize only middle messages
  - Return `(summary, range)` tuple

#### 2.4 Context Builder

**File:** `src/retrieval/context_builder.rs`

- Add preserved first messages to context
- Use `compacted_range` to determine context composition

## Database Schema v3

```sql
-- Conversations (unchanged)
CREATE TABLE conversations (...);

-- Messages (has_embedding from v1)
CREATE TABLE messages (
    id INTEGER PRIMARY KEY,
    conversation_id TEXT NOT NULL,
    role TEXT NOT NULL,
    content TEXT NOT NULL,
    timestamp INTEGER NOT NULL,
    importance REAL DEFAULT 0.5,
    has_embedding INTEGER DEFAULT 0  -- v1
);

-- Message chunks (has_embedding from v3)
CREATE TABLE message_chunks (
    id INTEGER PRIMARY KEY,
    message_id INTEGER NOT NULL,
    chunk_index INTEGER NOT NULL,
    content TEXT NOT NULL,
    start_offset INTEGER NOT NULL,
    end_offset INTEGER NOT NULL,
    created_at INTEGER NOT NULL,
    has_embedding INTEGER DEFAULT 0,  -- v3 NEW
    FOREIGN KEY (message_id) REFERENCES messages(id)
);

-- Index for missing embeddings (v3 NEW)
CREATE INDEX idx_chunks_missing_embedding 
    ON message_chunks(has_embedding) WHERE has_embedding = 0;
```

## Backward Compatibility

### ChatSession Serialization

```rust
// Old session without compacted_range
{
    "compacted_summary": "...",
    "messages_sent_to_llm": 15
}

// Deserializes to:
ChatSession {
    compacted_summary: Some("..."),
    compacted_range: None,  // default
    messages_sent_to_llm: 15
}

// Behavior: Use messages_sent_to_llm as fallback
// if compacted_range is None
```

### Migration Path

1. **Schema v2 → v3:** Add `has_embedding` column, safe migration
2. **Session JSON:** `compacted_range` defaults to None
3. **Context:** Falls back to `messages_sent_to_llm` if no range
