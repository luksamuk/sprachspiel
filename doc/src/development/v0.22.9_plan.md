# v0.22.9 - Context Framing for LLM Understanding

**Priority:** CRITICAL  
**Status:** COMPLETED  
**Date:** 2026-03-03  

---

## Problem

After implementing forced retrieval (v0.22.7), semantic retrieval works correctly:

- ✅ Session ID is stable across model switches
- ✅ Messages are preserved in SQLite after `/clear`
- ✅ Hybrid search returns relevant results
- ✅ `should_force_retrieve()` correctly detects post-clear state

**However, the LLM still says "I have no memory of previous conversations."**

### Root Cause

The LLM receives retrieved context in this format:

```xml
<retrieved_context>
<message index="1" timestamp="1709554800">
<role>user</role>
<content>What is the capital of France?</content>
</message>
</retrieved_context>
```

**The LLM doesn't understand:**
1. What `<retrieved_context>` represents
2. That these are messages from THIS conversation
3. That it should reference these topics when relevant

### Why Smaller Models Are More Affected

Models with smaller context windows (like ministral) have:
- Less capacity to infer context from unfamiliar tags
- Less "instruction following" capability
- More reliance on explicit framing

The `glm-5:cloud` with 198K context might figure it out, but `ministral` with smaller context needs explicit instructions.

---

## Decisions

### 1. Token Overhead vs. Clareza

**Decision:** Accept ~80 tokens overhead for framing.

**Rationale:** 
- 80 tokens is 0.04% of glm-5:cloud 198K context
- 80 tokens is 0.25% of ministral 32K context
- Clarity is worth the minimal cost

### 2. MEMORY Section in System Prompt

**Decision:** Add MEMORY section conditionally (only when retrieval happens).

**Rationale:**
- More efficient than adding to base prompt
- ~30 tokens saved when retrieval doesn't happen
- Simpler implementation

### 3. Message Retrieval Limit

**Decision:** Keep current limit (5 messages).

**Rationale:**
- Current: 5 relevant + 10 recent + summary
- Reasonable for 32K+ context models
- Models below 32K are not the target
- Research suggests 60K minimum for tool calling, we're well within limits

### 4. conversation_id in Retrieved Messages

**Decision:** Do NOT include conversation_id.

**Rationale:**
- Internal implementation detail
- Adds tokens without benefit to LLM
- LLM doesn't need to know about session IDs

### 5. Future: Recall Tool

**Decision:** Defer to future research (low priority).

**Rationale:**
- Current framing solution should work
- Tool-based recall would require more research
- Keep as future enhancement
- Add to roadmap as low priority

## Implementation Plan

### Phase 1: Improve Retrieved Context Framing

**File:** `src/retrieval/context_builder.rs`

**Location:** ~line 125-145

**Current Code:**
```rust
let mut retrieved_text = String::from("<retrieved_context>\n");
for (i, msg) in results.iter().enumerate() {
    retrieved_text.push_str(&format!(
        "<message index=\"{}\" timestamp=\"{}\">\n<role>{}</role>\n<content>{}</content>\n</message>\n",
        i + 1, msg.timestamp, msg.role, msg.content
    ));
}
retrieved_text.push_str("</retrieved_context>");
```

**New Code:**
```rust
let mut retrieved_text = String::from("<retrieved_context>\n");
retrieved_text.push_str("The following messages are from YOUR conversation history with this user.\n");
retrieved_text.push_str("They represent topics you have discussed together earlier.\n");
retrieved_text.push_str("Reference these when the user asks about previous topics.\n\n");
for (i, msg) in results.iter().enumerate() {
    retrieved_text.push_str(&format!(
        "<message index=\"{}\" timestamp=\"{}\">\n<role>{}</role>\n<content>{}</content>\n</message>\n",
        i + 1, msg.timestamp, msg.role, msg.content
    ));
}
retrieved_text.push_str("</retrieved_context>");
```

**Token Impact:** +50 tokens per retrieval

## Future Enhancement (Low Priority)

### Recall Tool

**Status:** Deferred

**Concept:** Allow LLM to call a `recall(query)` tool that explicitly searches conversation history.

**Benefits:**
- LLM has explicit control over what to recall
- Can search specific topics, not just rely on automatic retrieval
- Can request more context when needed

**Challenges:**
- Requires tool calling capability
- Need to define tool interface
- May conflict with automatic retrieval
- Need to research tool calling overhead

**Recorded in:** `doc/src/development/roadmap.md` as future tool (low priority)
