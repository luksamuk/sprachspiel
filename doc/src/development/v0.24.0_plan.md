**Priority:** HIGH

## Problem Statement

When searching conversation history, short user questions have high semantic similarity with the query but contain no information. Long assistant responses contain the information but have lower similarity due to semantic dispersion.

**Example:**
```
Query: "Wittgenstein"
Results:
  - [id=16] User: "Tem certeza que não conversamos antes sobre Wittgenstein?" (score: 0.85)
  - [id=10] User: "A gente já conversou a respeito do Como ler Wittgenstein?" (score: 0.82)
  - [id=14] User: "A gente já conversou a respeito do Como ler Wittgenstein?" (score: 0.80)
```

The ASSISTANT RESPONSES that follow these questions are NOT retrieved, even though they contain the actual information about Wittgenstein.

---

## Root Cause Analysis

### Semantic Similarity Bias

1. **Short messages (questions)**: High semantic density in few tokens → concentrated similarity score
2. **Long messages (responses)**: Semantic information spread across many tokens → dispersed similarity score
3. **RRF fusion**: Both keyword and semantic suffer from the same bias

### Why This Happens

When a user asks "What about Wittgenstein?", the query has high similarity with:
- The question itself (similar tokens)
- Other similar questions about Wittgenstein

But LOW similarity with:
- The actual answer (many tokens, dispersed semantics)

---

## Solution: Post-Retrieval Enrichment

### Approach

**When a user message is retrieved, automatically include the next assistant message from the same conversation.**

This ensures the LLM receives complete question-answer pairs, not just questions.

### Design Decisions

1. **Only for user messages**: Assistant messages don't need enrichment (they are already answers)
2. **Context limit is acceptable**: 5 messages + 5 answers = 10 messages total
3. **Implement in phases**: Phase 1 = enrichment, Phase 2 = RRF role weighting
4. **Used everywhere**: Both auto-context and remember tool use the same enrichment

**File:** `src/db/operations.rs`

Add function to enrich results:

```rust
/// Enrich search results with conversation context
/// 
/// For user messages, attach the next assistant message from the same conversation.
pub fn enrich_with_context(
    &self,
    results: Vec<SearchResult>,
) -> Result<Vec<SearchResult>> {
    let mut enriched = Vec::new();
    
    for result in results {
        let next_message = if result.role == "user" {
            self.get_next_message_by_role(
                result.message_id,
                &result.conversation_id,
                "assistant"
            )?
            .map(Box::new)
        } else {
            None
        };
        
        enriched.push(SearchResult {
            next_message,
            ..result
        });
    }
    
    Ok(enriched)
}
```

**File:** `src/retrieval/context_builder.rs`

Update context formatting to include next_message:

for msg in results.iter() {

    // If user message has an assistant response, include it
    if let Some(ref answer) = msg.next_message {
        retrieved_text.push_str(&format!(
            "<message id=\"{}\">\n<role>{}</role>\n<content>{}</content>\n</message>\n",

## Future Phases

### Phase 2 (v0.24.1): Role-Based RRF Weighting

Boost assistant messages in RRF scoring:
- Assistant weight: 1.5
- User weight: 1.0

This helps assistant responses rank higher in initial retrieval.

### Phase 3 (v0.25.0): Pair-Based Indexing

Store and embed question-answer pairs as units:
- Higher quality retrieval
- But requires re-indexing existing data
