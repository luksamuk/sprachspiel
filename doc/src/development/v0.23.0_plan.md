# v0.23.0 - Remember Tool & Context Enhancement

**Priority:** HIGH  
**Status:** IN PROGRESS  
**Date:** 2026-03-03

---

## Problem Statement

Even with v0.22.9 context framing, the LLM still struggles to:
1. Know when/how to retrieve MORE context (only receives 5 messages)
2. Understand HOW to reference retrieved messages
3. Search for topics NOT in the last query

The GLM-5:cloud model, even with 198K context, responds "I have no memory of previous conversations" because it doesn't have an explicit mechanism to request more context.

---

## Solution Overview

| Layer | Mechanism | Trigger |
|-------|-----------|---------|
| Auto-context | 5 relevant messages with IDs | System (always on when retrieval enabled) |
| Remember by ID | `remember(id="42")` | LLM explicit call |
| Remember by Query | `remember(query="topic")` | LLM explicit call |

**Key insight:** The LLM needs TWO things:
1. IDs in the retrieved context (to know what to ask for)
2. An explicit tool to request more (to ask)

---

## Technical Decisions

### 1. Thread-Local vs Task-Local Storage

**Decision:** Use `tokio::task_local!` instead of `thread_local!`.

**Rationale:**
- `thread_local!` is unsafe in async context (tasks can move between threads after `await`)
- `tokio::task_local!` preserves context for the duration of the async task
- Embeddings are not affected (EmbeddingClient is thread-safe via `Arc`)

### 2. Tool Name

**Decision:** `remember` (not `recall`).

**Rationale:**
- More natural language
- clearer semantic meaning
- Short and memorable

### 3. Default Limit

**Decision:** Default 5, max 10 results.

**Rationale:**
- Matches the auto-context limit
- 10 is enough for deep exploration
- LLM can always make another query

### 4. Anonymous Sessions

**Decision:** Don't register the tool at all.

**Rationale:**
- No database available
- Cleaner UX than showing an error
- User chose ephemeral session

### 5. Message ID Format

**Decision:** Use database ID directly (e.g., `id="42"`).

**Rationale:**
- Minimal token overhead
- Direct database lookup
- Simple for LLM to use

use std::sync::Arc;
use crate::db::Database;
use crate::embeddings::EmbeddingClient;

tokio::task_local! {
    pub static REMEMBER_DB: Arc<Database>;
    pub static REMEMBER_EMBEDDING: Arc<EmbeddingClient>;
}

/// Helper to set context during coordinator execution
pub async fn with_context<F, T>(
    db: Arc<Database>,
    embedding: Arc<EmbeddingClient>,
    f: F,
) -> T
where
    F: std::future::Future<Output = T>,
{
    REMEMBER_DB.scope(db, async {
        REMEMBER_EMBEDDING.scope(embedding, async {
            f.await
        })
    }).await
}
```

### Phase 3: Remember Tool Implementation

**File:** `src/tools/remember.rs` (NEW)

```rust
use crate::debug_tools::{log_tool_call, log_tool_result};
use crate::tools::context::{REMEMBER_DB, REMEMBER_EMBEDDING};
use ollama_rs::function;

/// Recall messages from your conversation history.
///
/// Use this tool to:
/// 1. Get the full content of a specific message (by ID from retrieved context)
/// 2. Search for topics not in the current context (by query)
///
/// # Arguments
/// * `id` - ID of message to retrieve (from retrieved context). Optional.
///   - Example: "42" to get message with id="42"
/// * `query` - Search query for semantic search. Optional.
///   - Example: "Wittgenstein" to find messages about that topic
/// * `limit` - Max results for query (default: 5, max: 10). Optional.
///
/// # Returns
/// - For id: Full message content with metadata
/// - For query: List of matching messages with IDs and excerpts
///
/// # Examples
/// ```ignore
/// remember(id="42")                           // Get message 42
/// remember(query="Wittgenstein")              // Search for Wittgenstein
/// remember(query="philosophy", limit="10")    // Search with limit
/// ```
#[ollama_rs::function]
pub async fn remember(
    id: Option<String>,
    query: Option<String>,
    limit: Option<String>,
) -> Result<String, Box<dyn std::error::Error + Send + Sync>> {
    log_tool_call("remember", &[
        ("id".to_string(), id.clone().unwrap_or_default()),
        ("query".to_string(), query.clone().unwrap_or_default()),
        ("limit".to_string(), limit.clone().unwrap_or_else(|| "5".to_string())),
    ]);
    
    // Validate parameters
    if id.is_none() && query.is_none() {
        let err = "Error: Provide either id or query parameter. Examples:\n\
                   - remember(id=\"42\") to get a specific message\n\
                   - remember(query=\"Wittgenstein\") to search by topic";
        log_tool_result("remember", err);
        return Ok(err.to_string());
    }
    
    // Parse limit
    let limit_num = limit
        .and_then(|l| l.parse::<usize>().ok())
        .unwrap_or(5)
        .min(10);
    
    // Get task-local context
    let result = match (REMEMBER_DB.try_with(|db| db.clone()), REMEMBER_EMBEDDING.try_with(|e| e.clone())) {
        (Ok(db), Ok(embedding)) => {
            if let Some(id_str) = id {
                remember_by_id(&db, &id_str).await
            } else if let Some(q) = query {
                remember_by_query(&db, &embedding, &q, limit_num).await
            } else {
                unreachable!()
            }
        }
        _ => "Error: Conversation database not available. You may be in an anonymous session.".to_string(),
    };
    
    log_tool_result("remember", &result);
    Ok(result)
}

async fn remember_by_id(db: &Arc<Database>, id_str: &str) -> String {
    let id: i64 = match id_str.parse() {
        Ok(id) => id,
        Err(_) => return format!("Error: Invalid message ID '{}'. Must be a number.", id_str),
    };
    
    match db.get_message_by_id(id) {
        Ok(Some(msg)) => {
            let role_label = match msg.role.as_str() {
                "user" => "User",
                "assistant" => "Assistant",
                "system" => "System",
                "tool" => "Tool",
                _ => &msg.role,
            };
            
            let timestamp = chrono::DateTime::from_timestamp(msg.timestamp, 0)
                .unwrap_or_else(chrono::Utc::now);
            
            format!(
                "**Message {}**\nRole: {}\nTimestamp: {}\n\n---\n{}\n---",
                msg.message_id,
                role_label,
                timestamp.format("%Y-%m-%d %H:%M"),
                msg.content
            )
        }
        Ok(None) => format!("Error: Message {} not found. It may have been deleted.", id),
        Err(e) => format!("Error: Failed to retrieve message {}: {}", id, e),
    }
}

async fn remember_by_query(
    db: &Arc<Database>,
    embedding_client: &Arc<EmbeddingClient>,
    query: &str,
    limit: usize,
) -> String {
    let embedding = match embedding_client.embed(query).await {
        Ok(emb) => emb,
        Err(e) => return format!("Error: Failed to generate embedding: {}", e),
    };
    
    let results = match db.search_hybrid(query, &embedding, None, limit, 0.4, 0.6) {
        Ok(r) => r,
        Err(e) => return format!("Error: Search failed: {}", e),
    };
    
    if results.is_empty() {
        return "No messages found matching your query.".to_string();
    }
    
    let mut output = format!("**Found {} message(s)**\n\n", results.len());
    
    for msg in results {
        let role_label = match msg.role.as_str() {
            "user" => "👤 User",
            "assistant" => "🤖 Assistant",
            _ => &msg.role,
        };
        
        let content = if msg.content.len() > 200 {
            format!("{}...", &msg.content[..200])
        } else {
            msg.content.clone()
        };
        
        output.push_str(&format!(
            "**[id={}]** {} (score: {:.2})\n{}\n\n",
            msg.message_id, role_label, msg.score, content
        ));
    }
    
    output.push_str("Use message IDs to retrieve full content: remember(id=\"N\")");
    output
}
```

## Risks and Mitigations

### Risk: LLM doesn't use remember tool

**Mitigation:** 
- Strong MEMORY TOOLS section with examples
- IDs in context make it obvious
- If still not used, increase framing clarity

### Risk: Performance overhead for embedding generation

**Mitigation:**
- Only generate embedding when tool is called
- Limit to 5/10 results
- EmbeddingClient already optimized

### Risk: Task-local scope issues

**Mitigation:**
- Comprehensive testing
- Graceful fallback when context unavailable
- Clear error messages
